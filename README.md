# Опора

**ML-помощник для поиска ответов по учебным материалам.**

«Опора» помогает студентам находить информацию в лекциях и методичках. Пользователь загружает документ и задаёт вопрос обычным языком. Сервис находит подходящие фрагменты и формирует ответ с цитатами и ссылками на страницы.

> **Статус:** проектирование MVP. В этом README описаны целевые возможности и предлагаемая архитектура. Реализация приложения ещё не представлена.

## Какую проблему решаем

Требования к практическим работам, определения и пояснения часто находятся в длинных документах. Поиск по словам помогает, когда известна точная формулировка. Если вопрос сформулирован иначе, нужное место приходится искать вручную.

«Опора» должна сократить этот путь: найти фрагмент по смыслу, объяснить его и дать возможность сразу проверить ответ по исходному материалу.

## Пример использования

1. Студент загружает методичку по дисциплине.
2. Задаёт вопрос: «Какие разделы нужно включить в отчёт по первой практике?»
3. Получает краткий перечень требований.
4. Открывает цитату и страницу, на которой эти требования указаны.

Если сведения не найдены, сервис должен сообщить об этом и предложить уточнить вопрос или добавить другой документ.

## Возможности MVP

Для первой версии выбран один сценарий: работа с материалами одной дисциплины.

Планируется реализовать:

- загрузку PDF с текстовым слоем и файлов TXT;
- извлечение текста с сохранением связи с документом и страницей;
- поиск фрагментов по смыслу вопроса;
- формирование ответа на основе найденных фрагментов;
- отображение цитаты, названия файла и страницы для PDF;
- сообщение об отсутствии достаточной информации;
- обратную связь о полезности и ошибках ответа.

Распознавание сканов и рукописей, обработка аудио и интеграции с университетскими системами выходят за рамки первой версии.

## Как используется ML

В основе проекта - **RAG (Retrieval-Augmented Generation)**: формирование ответа с опорой на найденные материалы.

### Подготовка документов

Из загруженного файла извлекается текст. Он разбивается на фрагменты, для каждого из которых сохраняется источник. Модель эмбеддингов преобразует фрагменты в числовые представления для смыслового поиска.

### Обработка вопроса

Вопрос преобразуется той же моделью. Система находит близкие по смыслу фрагменты и передаёт их языковой модели вместе с вопросом. Модель формирует ответ, а интерфейс показывает связанные источники.

### Проверка результата

Ссылки должны вести к реально существующим фрагментам. При недостатке подтверждений система должна сообщать об этом. Наличие цитаты не гарантирует правильности вывода: пользователь должен иметь возможность прочитать её в контексте.

Для MVP предполагается использовать предобученные модели. Основная работа команды — подготовка документов, настройка поиска, проверка качества ответов и разработка интерфейса.

## Предлагаемая архитектура

| Компонент | Назначение |
| --- | --- |
| Веб-интерфейс | Загрузка файлов, ввод вопроса, просмотр ответа и источника |
| Сервер на Python | Обработка документов и управление запросами |
| Извлечение текста | Чтение PDF и TXT, сохранение метаданных источника |
| Модель эмбеддингов | Числовые представления текста и вопросов |
| Векторный индекс | Поиск релевантных фрагментов |
| Языковая модель | Формирование ответа по найденному контексту |

Конкретные модели и библиотеки будут выбраны после проверки качества на русскоязычных учебных материалах и оценки затрат на обработку запросов.

## Как будем оценивать качество

Для проверки нужен набор вопросов с размеченными ответами и фрагментами источников. В него также войдут вопросы, на которые в документах нет ответа.

| Критерий | Что проверяем |
| --- | --- |
| Качество поиска | Попадает ли нужный фрагмент в первые пять результатов — Recall@5 |
| Подтверждённость ответа | Следуют ли утверждения из найденных материалов |
| Корректность ссылок | Ведут ли ссылки к нужному документу и фрагменту |
| Отказ при недостатке данных | Сообщает ли система об отсутствии ответа |
| Удобство | Сколько времени занимает получение и проверка ответа |

Смысловой поиск будет сравниваться с поиском по ключевым словам. Материалы для итогового тестирования необходимо отделить от материалов, используемых для настройки.

Результаты измерений будут опубликованы после появления работающего прототипа.

## Ограничения

- Качество ответа зависит от полноты и качества загруженных материалов.
- Модель может ошибиться или неверно связать ответ с цитатой.
- Таблицы, формулы и сложная вёрстка могут затруднять извлечение текста.
- В первой версии поддерживаются документы с доступным текстом; сканы требуют отдельного этапа распознавания.
- Поиск ограничен загруженными материалами. Актуальность требований нужно проверять по версии исходного документа.
